# 0009: 攻克痛点2——敏感命令黑盒审查恐惧与意图透视契约

学习者选择优先拔掉第 2 根刺：**面对 Agent 提出的敏感/高危命令时，无法评估破坏性与影响面，沦为盲目确认背锅侠**。

## 核心内化点（建立安全掌控力）
1. **黑盒恐惧的根因**：Agent 给出的是“机器执行代码（How）”，却隐藏了“底层影响面与副作用（What & Impact）”。人类认知带宽无法在 3 秒内对几十行复杂 Shell/脚本做完静态分析。
2. **工程防御机制（Intent-Impact-Rollback 三联契约）**：
   - 不允许裸命令审批弹窗；
   - 强制前置执行三联透视输出：
     1. **影响目标（Target）**：具体碰哪个目录/文件/端口？只读还是覆写？
     2. **爆炸半径（Blast Radius）**：系统影响面、是否影响非当前工程路径？
     3. **回滚救生圈（Rollback Plan）**：一旦执行失误，怎样一条命令还原？
3. **空跑预检（Dry-run Pattern）**：
   - 优先通过 `git status`、`find ... -type f`、`rsync --dry-run` 等只读探针打前站，展示拟操作清单。

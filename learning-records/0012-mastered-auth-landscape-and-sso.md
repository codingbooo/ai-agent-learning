# 0012: 掌握现代主流认证全景与 SSO 原理

学习者对现实企业级系统的认证鉴权体系（SSO、Cookie、Token、账号密码）提出核心疑问。
正式完成 Lesson 0008：《主流认证全景：SSO 到底是何方神圣？》。

## 核心内化点（打破认知黑盒）
1. **Cookie + Session（传统 Web 房卡模式）**：
   - 依赖浏览器自动携带，服务端内存/Redis 存状态。易受 CSRF 攻击、短效易过期，对自动化 Agent 极不友好。
2. **Token / JWT（现代 App 与微服务工作证）**：
   - Android 最熟悉的 `Bearer Token`。自包含签名，服务端无状态校验。短效 AccessToken 换取高安全性，长效 RefreshToken 维持静默刷新。
3. **SSO（Single Sign-On 单点登录，迪士尼手环模式）**：
   - 彻底解决企业内“几十个系统各自一套账密”的灾难。
   - 架构核心：将认证剥离给独立的“统一身份认证中心（IdP，如飞书/Okta/Keycloak）”。
   - 流程：业务系统无登录态 ➔ 重定向到 SSO 认证中心 ➔ 用户认证一次 ➔ 签发授权票据（Ticket/Code）重定向回业务系统 ➔ 换取局部登录态。访问第二家系统时，认证中心直接秒验，无需再次输入账密。
4. **PAT（Personal Access Token，Agent 的专属通行副卡）**：
   - 机器与自动化脚本接入的唯一终极正道。绕开人类专属的图形/短信验证码，精准限定权限范围，长效受控。

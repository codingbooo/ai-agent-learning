LESSON 0008 · 认证全景 身份识别心智

主流认证全景：SSO 到底是何方神圣？

从酒店房卡、免检手环到数字身份证：透视现代 Web、App 与机器人的身份凭证体系。

🏨 1. Cookie & Session 传统 Web 专属
💡 隐喻：酒店房卡（钥匙在门锁前台匹配）
输入账号密码后，服务端存状态，给浏览器塞一个 SessionID。浏览器后续自动携带。对 App/脚本极不友好，易过期。
🪪 2. Token / JWT App & API 标准
💡 隐喻：防伪盖章工作证（自包含权限信息）
Android 最常见的 Bearer Token。服务端无需查数据库，凭数学签名即可验真。短效 AccessToken + 长效 RefreshToken 配合。
🌐 3. SSO (Single Sign-On) 企业级王道
💡 隐喻：迪士尼通票手环（一处检票，玩遍全园）
单点登录：公司有 GitLab、Jira、OA、报销等几十个系统。统一把认证甩给一个独立认证中心（如飞书/企微/Okta）。只需登录一次，其他系统免密通行！
🤖 4. PAT (Personal Access Token) Agent 破局首选
💡 隐喻：专属访客通行副卡（给管家的备用钥匙）
让脚本和机器人干活的唯一正道！在网页设置里主动给脚本签发一个长效/特定权限的 Token，彻底绕开验证码与登录页。
🎯 针对你的痛点：Agent 到底该用哪个？
• 下策：让 Agent 去网页输账号密码/短信验证码（100% 被反爬卡死）；
• 中策：从浏览器 F12 复制已登录的 Cookie（能用几天，但需人工刷新）；
• 上策：在 SSO 或系统后台生成一个 Personal Access Token (PAT)，长效免密闭环！

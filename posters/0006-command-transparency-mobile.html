LESSON 0006 · 命令掌控权 告别盲目审批

拆解黑盒：高危命令透视契约

不再当担惊受怕的背锅侠。建立 3 项硬核审查标准，一眼看穿每条指令的底线与风险。

❌ 过去的痛苦：黑盒盲审 恐慌背锅
"是否允许执行: find . -name '*.bak' -exec rm -rf {} +"
(你不敢点同意，因为不知道会不会连带删掉系统或未备份的代码)
✓ 建立契约：意图与边界三联单 透明掌控
🎯 目标：仅扫描当前项目 ./cache/ 目录
💥 影响面：预估清理 3 个文件，不碰任何源码
🛟 回滚：已由 git 托管，随时执行 git checkout
🛡️ 必须强制 AI 遵守的“审查三原则”
1. 爆炸半径限制 (Blast Radius)
操作范围必须锁定在当前项目根目录内！严禁碰 ~/.ssh、/etc、全局 node_modules 或系统根目录。
2. 空跑预检模式 (Dry-Run First)
只要涉及删除或批量改名，严禁直接执行！必须先用只读命令（如 ls、--dry-run）列出拟变动清单。
3. 必须提供救生圈 (Rollback Plan)
高危操作前，必须说明：如果执行报错或删错，一条什么命令能够瞬间原样恢复。
📋 拷打 AI 的专属指令模板（直接复制使用）
"先不要执行！请先向我汇报：
1. 这条命令会改动/删除哪几个具体文件？
2. 它会不会影响当前目录之外的文件？
3. 如果改坏了，用哪一条命令可以一键回滚？"

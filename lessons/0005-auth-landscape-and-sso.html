Lesson 0005 · 凭证工程与实战破局

认证全景与实战破局：从 SSO 到 Agent 通行副卡

剖析 Cookie、Token、SSO 与 PAT 的物理本质，彻底终结肉身搬砖与登录墙卡死。

一、 核心认知：四大主流认证体系的本质映射

很多工程师习惯在网页端点选，却不清楚浏览器背后究竟发生了什么。我们用一套精准的现实隐喻来还原底层网络协议：

🏨 1. Cookie & Session —— 酒店房卡模式（传统 Web）

你在登录页输账密 ➔ 服务端在内存/Redis 建一个 Session ➔ 往浏览器 Set-Cookie: sessionId=xyz。后续浏览器发任何请求都会自动带上这串字符。

⚠️ 为什么 Agent 最怕它： 房卡不仅会频繁过期，而且通常伴随着复杂的图形/短信验证码与防 CSRF 机制。让 Agent 模拟浏览器点选，极容易因为页面微调或验证码而全盘崩溃。

🪪 2. Token / JWT —— 防伪工作证模式（App & 微服务）

Android 工程师最熟悉的 Authorization: Bearer <Token>。服务端自己不保留状态，直接把用户 ID、角色和过期时间签名加密成一段字符。任何服务只要用公钥验真即可秒级放行。

💡 双 Token 架构： 短效 AccessToken（如 15 分钟）保证安全，长效 RefreshToken（如 30 天）放在本地安全存储中做静默刷新，用户完全无需反复登录。

🌐 3. SSO (Single Sign-On) —— 迪士尼通票手环模式（企业级核心）

公司内部几十个系统（GitLab、Jira、OA、报销系统）各建一套账号密码是灾难。SSO 把鉴权抽离给一个独立的统一认证中心（IdP，如飞书/Okta/Keycloak）：

  1. 你访问 GitLab，GitLab 发现你没登录，将你重定向至 SSO 统一认证中心；
  2. 你在 SSO 认证中心刷一次工牌或扫码；
  3. 认证中心给你签发授权票据（Ticket/Code）并重定向回 GitLab；
  4. 下午你访问 Jira 时，Jira 再次把你踢到认证中心，认证中心认出你已登录，直接免密秒发门票送回 Jira！

✓ 核心价值： 一处登录，处处通行；员工离职只需在认证中心一键停用，全公司系统立即阻断。

🤖 4. PAT (Personal Access Token) —— 专属访客副卡（Agent 自动化正道）

在系统后台（如 GitLab/GitHub 的 Developer Settings）主动给自己签发的机器专用 Token。精准圈定权限范围、设置长有效期、彻底免除人机验证码！

二、 Agent 破解登录墙的三重境界

[下策 · 打杂死路] 让 Agent 启动无头浏览器，肉身去网页输账密/点 SSO 扫码 ➔ 100% 被验证码拦截，频繁喊人。
[中策 · 临时应急] 人在浏览器完成一次 SSO，按 F12 抓出有效 Cookie，存入本地文件供脚本读取 ➔ 免密跑几天，失效后需人工刷新。
[上策 · 工业正道] 在该后台或 SSO 中心申请一个 PAT / API Key，注入本地环境变量，Agent 封装为 Tool 静默调用 ➔ 全自动终身免维护！

三、 交互式自测：为你的后台对齐方案

❓ 实战决策题

你现在要让 Agent 每天凌晨自动拉取公司内网某个系统的报表，该系统只支持公司内部 SSO 扫码登录，没有开放生成长效 PAT 的权限。下列哪种工程组合拳能最大程度减少你的人工打杂成本？

A. 每天凌晨定闹钟爬起来，人工扫码通过后让 Agent 开始跑
B. 人工登录一次并抓取 Session 存为本地文件，脚本每天优先读取，仅在 401 失败时才通知你扫码续期
C. 把你的个人飞书/企微账号密码明文写在 Agent 的提示词里让它自动模拟扫码
D. 让 Agent 反复发送空请求，直到系统防御机制失效放行
